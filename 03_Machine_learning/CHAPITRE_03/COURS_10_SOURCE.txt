Partie I — Les fondamentaux de l'évaluation
1. Les trois niveaux d'évaluation
Un modèle doit être évalué selon trois dimensions complémentaires.

1. Performance prédictive

Le modèle prédit-il correctement les résultats ? Nous utilisons Accuracy, Precision, Recall, F1, ROC-AUC, MAE, RMSE ou R² selon le problème.




2. Généralisation et robustesse

Le modèle fonctionne-t-il sur de nouvelles données, sur différentes périodes et lorsque la distribution des données change ?




3. Utilité métier

Le modèle est-il suffisamment explicable, rapide, stable, calibré et compatible avec les contraintes opérationnelles ?



2. Train, Validation et Test
Rappelons le rôle des trois ensembles.
Exemple de découpage 70 / 15 / 15
Train 70 %

Val 15 %

Test 15 %


Le Train sert à ajuster les paramètres, la Validation à sélectionner les hyperparamètres et les modèles, et le Test à réaliser l'évaluation finale indépendante.

Le découpage 70/15/15 est seulement un exemple. Pour les données temporelles, il est généralement préférable de respecter la chronologie plutôt que d'effectuer un découpage aléatoire.

Partie II — Classification : comprendre la Confusion Matrix
3. La matrice de confusion
La Confusion Matrix compare les classes réelles aux classes prédites.

En classification binaire :
	Prédit négatif	Prédit positif
Réel négatif	TN	FP
Réel positif	FN	TP

Dans un problème de défaut de crédit :
- TP — True Positive : une entreprise en défaut est correctement identifiée.
- TN — True Negative : une entreprise sans défaut est correctement identifiée.
- FP — False Positive : une entreprise sans défaut est classée à risque.
- FN — False Negative : une entreprise en défaut n'est pas détectée.
Le coût de ces deux types d'erreurs peut être très différent.

5. Accuracy
\[
\boxed{
Accuracy=\frac{TP+TN}{TP+TN+FP+FN}
}
\]

L'Accuracy représente la proportion de prédictions correctes.

Elle est simple à comprendre, mais peut être trompeuse sur les datasets déséquilibrés.
Exemple
Supposons 10 000 entreprises :
- 9 500 sans défaut.
- 500 en défaut.
Un modèle qui prédit toujours « pas de défaut » obtient :
\[
Accuracy=\frac{9500}{10000}=95\%
\]

Pourtant, il ne détecte aucun défaut.

C'est pourquoi nous devons examiner d'autres métriques.
6. Precision
\[
\boxed{
Precision=\frac{TP}{TP+FP}
}
\]

La Precision répond à la question :

Parmi les observations prédites positives, combien sont réellement positives ?

Elle est importante lorsque les fausses alertes sont coûteuses.
7. Recall / Sensitivity
\[
\boxed{
Recall=\frac{TP}{TP+FN}
}
\]

Le Recall répond à la question :

Parmi les observations réellement positives, combien avons-nous détectées ?

Dans un système de détection de défaut, un faible Recall signifie que de nombreux défauts ne sont pas détectés.
8. Specificity
\[
\boxed{
Specificity=\frac{TN}{TN+FP}
}
\]

La Specificity mesure la proportion de négatifs correctement identifiés.

Elle est liée au False Positive Rate :
\[
\boxed{FPR=1-Specificity}
\]

9. F1-score
Le F1-score combine Precision et Recall avec leur moyenne harmonique :
\[
\boxed{
F1=2\frac{Precision\times Recall}{Precision+Recall}
}
\]

Un F1 élevé nécessite généralement un équilibre entre Precision et Recall.

Mais ce n'est pas toujours la meilleure métrique métier : il ne tient pas compte directement des coûts économiques des erreurs.
10. Balanced Accuracy
Pour les classes déséquilibrées :
\[
\boxed{
Balanced\ Accuracy=\frac{Sensitivity+Specificity}{2}
}
\]

Elle donne un poids égal à la capacité de détection de chaque classe, indépendamment de leur fréquence.

Partie III — ROC Curve et ROC-AUC
11. Pourquoi avons-nous besoin d'une courbe ROC ?
Un modèle de classification peut produire un score continu.

Pour transformer ce score en classe, nous choisissons un seuil.

Par exemple :
\[
\hat y=
\begin{cases}
1 & \text{si } P(Y=1\mid X)\ge0.5\\
0 & \text{sinon}
\end{cases}
\]

Mais pourquoi choisir 0,5 ?

En pratique, le seuil dépend du problème métier.

La ROC Curve montre comment évoluent le True Positive Rate et le False Positive Rate lorsque nous modifions ce seuil.
\[
TPR=\frac{TP}{TP+FN}
\]

\[
FPR=\frac{FP}{FP+TN}
\]

12. Comprendre la ROC-AUC
La ROC-AUC mesure l'aire sous la courbe ROC.

Modèle performantClassification aléatoire

00,250,50,75100.10.20.30.40.50.60.70.80.91









Courbes illustratives. Les performances représentées ne proviennent pas d'un modèle entraîné.






Interprétation :
- ROC-AUC = 1 : discrimination parfaite.
- ROC-AUC = 0,5 : performance équivalente à un classement aléatoire.
- ROC-AUC inférieure à 0,5 : classement systématiquement défavorable, selon l'orientation du score.
Une ROC-AUC de 0,85 signifie qu'une observation positive choisie aléatoirement a environ 85 % de chances d'obtenir un score supérieur à celui d'une observation négative choisie aléatoirement, en tenant compte des égalités selon la convention de l'AUC.
13. Le coefficient de Gini
En risque de crédit, on utilise souvent :
\[
\boxed{Gini=2\times ROC\text{-}AUC-1}
\]

Exemple :
\[
AUC=0.85
\]

Alors :
\[
Gini=2(0.85)-1=0.70
\]

Un Gini de 0,70 correspond donc à une ROC-AUC de 0,85.

Attention : il s'agit du Gini de discrimination, différent de l'impureté de Gini des arbres de décision.

Partie IV — Precision-Recall Curve et PR-AUC
14. Pourquoi la ROC-AUC ne suffit-elle pas ?
La ROC-AUC est utile pour évaluer la capacité de classement.

Mais sur un dataset fortement déséquilibré, elle peut sembler satisfaisante alors que la Precision des alertes est faible.

Prenons 10 000 observations avec 100 positifs.

Un modèle détecte 80 positifs, mais génère 400 fausses alertes.

Alors :
\[
Recall=\frac{80}{100}=80\%
\]

\[
Precision=\frac{80}{80+400}\approx16.7\%
\]

Le Recall est élevé, mais la majorité des alertes sont fausses.
15. Precision-Recall Curve
La PR Curve représente :
- Recall sur l'axe horizontal.
- Precision sur l'axe vertical.
Elle est particulièrement informative pour les classes rares.

En scikit-learn, on utilise souvent Average Precision (AP) :
from sklearn.metrics import average_precision_score



L'Average Precision résume la courbe Precision-Recall par une moyenne pondérée des précisions aux différents niveaux de rappel.

Elle ne doit pas être confondue avec toutes les méthodes possibles de calcul de l'aire trapézoïdale sous la courbe PR.
16. Quand utiliser ROC-AUC ou Average Precision ?
Situation	Métrique intéressante
Comparer la discrimination globale	ROC-AUC
Classe positive rare	Average Precision
Limiter les fausses alertes	Precision
Détecter le maximum de positifs	Recall
Équilibrer Precision et Recall	F1
Évaluer des probabilités	Brier Score, Log-loss

Dans les applications critiques, il est préférable de suivre plusieurs métriques complémentaires.

Partie V — Choisir le seuil de décision
17. Pourquoi 0,5 n'est pas toujours optimal ?
En classification, le seuil de 0,5 est courant, mais pas universel.

Dans un système de détection de fraude ou de défaut, nous pouvons vouloir détecter davantage de positifs.

Diminuer le seuil augmente généralement le Recall, mais augmente aussi les fausses alertes.

Augmenter le seuil diminue généralement les fausses alertes, mais peut faire manquer davantage de positifs.

19. Optimisation selon les coûts métier
Supposons :
- Coût d'un False Positive : 100 DT.
- Coût d'un False Negative : 2 000 DT.
Une fonction de coût simple serait :
\[
\boxed{
Coût=100\times FP+2000\times FN
}
\]

Dans ce contexte, manquer un défaut est beaucoup plus coûteux que générer une fausse alerte.

Le seuil optimal doit donc être sélectionné en tenant compte de cette asymétrie.

En pratique, les coûts doivent être estimés à partir de la réalité métier, et pas inventés pour optimiser artificiellement le modèle.

Partie VI — Calibration des probabilités
20. Discrimination versus Calibration
C'est l'une des distinctions les plus importantes de tout ce chapitre.
Discrimination
Un modèle discriminant donne généralement des scores plus élevés aux observations positives qu'aux observations négatives.

Nous l'évaluons avec ROC-AUC, Gini ou KS.
Calibration
Un modèle calibré produit des probabilités cohérentes avec les fréquences observées.

Par exemple, parmi les observations auxquelles le modèle attribue une probabilité proche de 10 %, environ 10 % devraient être positives, sous réserve d'un échantillon suffisamment grand et représentatif.

Un modèle peut avoir une excellente ROC-AUC mais une mauvaise calibration.

22. Brier Score
Le Brier Score mesure l'erreur quadratique des probabilités prédites.
\[
\boxed{
BS=\frac1n\sum_{i=1}^{n}(p_i-y_i)^2
}
\]

Pour une cible binaire :
- 0 correspond à des prédictions probabilistes parfaites.
- Une valeur plus élevée signifie une erreur plus importante.
Le Brier Score combine des aspects de calibration et de discrimination. Il ne mesure donc pas exclusivement la calibration.
23. Log-loss
La Log-loss est :
\[
\boxed{
LogLoss=-\frac1n\sum_{i=1}^{n}
\left[y_i\log(p_i)+(1-y_i)\log(1-p_i)\right]
}
\]

Elle pénalise fortement les prédictions très confiantes lorsqu'elles sont incorrectes.
Exemple
Prédire une probabilité de 0,99 pour un événement qui ne se produit pas entraîne une forte pénalité.

La Log-loss est donc particulièrement sensible aux erreurs de confiance.
24. Calibrer un modèle
Avec scikit-learn :

Deux approches courantes sont :
- Sigmoid / Platt Scaling : calibration paramétrique avec une fonction sigmoïde.
- Isotonic Regression : calibration non paramétrique et monotone, plus flexible mais potentiellement plus sensible au surapprentissage lorsque les données sont limitées.
La calibration doit être réalisée sans fuite d'information et évaluée sur des données indépendantes.

Partie VII — Les métriques de régression
25. MAE — Mean Absolute Error
\[
\boxed{
MAE=\frac1n\sum_{i=1}^{n}|y_i-\hat y_i|
}
\]

La MAE mesure l'erreur absolue moyenne.

Elle s'exprime dans la même unité que la cible.

Par exemple, une MAE de 500 DT signifie une erreur absolue moyenne de 500 DT.
26. MSE — Mean Squared Error
\[
\boxed{
MSE=\frac1n\sum_{i=1}^{n}(y_i-\hat y_i)^2
}
\]

La MSE pénalise fortement les grandes erreurs.

Elle est sensible aux observations atypiques.
27. RMSE — Root Mean Squared Error
\[
\boxed{
RMSE=\sqrt{\frac1n\sum_{i=1}^{n}(y_i-\hat y_i)^2}
}
\]

La RMSE est la racine carrée de la MSE.

Elle s'exprime dans l'unité de la cible.
28. R² — Coefficient de détermination
\[
\boxed{
R^2=1-
\frac{\sum_i(y_i-\hat y_i)^2}
{\sum_i(y_i-\bar y)^2}
}
\]

Interprétation :
- R² = 1 : prédictions parfaites.
- R² = 0 : performance égale à une prédiction constante de la moyenne sur les données évaluées.
- R² inférieur à 0 : performance inférieure à cette baseline.
R² peut être négatif sur le test.
29. Comparaison des métriques
Métrique	Sensibilité aux grandes erreurs	Unité
MAE	Modérée	Même unité que y
MSE	Forte	Unité au carré
RMSE	Forte	Même unité que y
R²	Dépend des erreurs quadratiques	Sans unité

31. Pourquoi un seul Train/Test Split ne suffit-il pas toujours ?
Un modèle peut obtenir de bons résultats sur un découpage particulier, mais des résultats moins bons sur un autre.

La Cross-Validation permet d'estimer la variabilité de sa performance.

À chaque itération, un fold sert à la validation et les autres à l'entraînement.

Nous calculons ensuite :
\[
\bar S=\frac1K\sum_{k=1}^{K}S_k
\]

Nous pouvons aussi mesurer la dispersion des scores.
32. Stratified K-Fold
Pour la classification déséquilibrée, StratifiedKFold préserve approximativement la proportion des classes dans chaque fold.
from sklearn.model_selection import StratifiedKFold



C'est souvent préférable à un K-Fold classique dans ce contexte.
33. Time Series Split
Pour les données temporelles, nous devons éviter d'utiliser le futur pour prédire le passé.

Par exemple :
Validation chronologique




























Bleu : historique utilisé pour entraîner. Orange : période future de validation. Gris : périodes non utilisées dans le fold.
Dans un projet de risque de crédit, une validation hors période est particulièrement importante pour vérifier la robustesse du modèle.
34. Nested Cross-Validation
La Nested Cross-Validation utilise deux boucles :
- Une boucle interne pour sélectionner les hyperparamètres.
- Une boucle externe pour évaluer la procédure complète de sélection.
Elle permet d'obtenir une estimation moins biaisée de la performance de la procédure de tuning que la réutilisation des mêmes folds pour sélectionner et évaluer.

Elle est surtout utile lorsque le dataset est limité et que nous souhaitons comparer rigoureusement plusieurs procédures de modélisation.

Performance

39. Interprétabilité : Feature Importance, Permutation et SHAP
Feature Importance
Les modèles à arbres peuvent fournir des mesures d'importance des variables.

Mais ces mesures ne sont pas toujours directement comparables entre modèles.

Certaines méthodes basées sur la réduction d'impureté peuvent favoriser les variables comportant de nombreuses valeurs distinctes.
Permutation Importance
L'idée consiste à permuter une variable sur un jeu d'évaluation, puis à mesurer la dégradation de performance.

Si la performance diminue fortement, la variable est importante pour ce modèle selon cette métrique.

Attention : les variables fortement corrélées peuvent rendre cette interprétation difficile.
SHAP
SHAP fournit des contributions des features à une prédiction par rapport à une valeur de référence, selon la méthode et le cadre utilisés.

C'est un outil d'explication des modèles, pas une preuve de causalité.
